Конфиденциальность в Brand Brief Studio

Здесь описан фактический путь данных в Brand Brief Studio: что остаётся в браузере, что отправляется при AI-генерации, какие технические данные используются и как работает необязательная аналитика.

Черновик миграции. Политика подготовлена под российскую production-архитектуру. Её нельзя считать финальной публичной юридической политикой до заполнения данных оператора, проверки production-настроек Yandex Cloud и выполнения применимых действий перед Роскомнадзором.

2. Локальные данные в браузере

Черновик анкеты сохраняется в этом браузере, чтобы работу можно было продолжить позже. Также локально хранятся до восьми последних брифов для каждого языка интерфейса. Запись недавнего брифа содержит исходные данные анкеты, сгенерированный или локальный результат, evidence-метаданные, альтернативные направления и локальную временную метку.

Эти записи используют Local Storage браузера. Brand Brief Studio не синхронизирует их с аккаунтом пользователя или собственной серверной базой. Они остаются до удаления пользователем, очистки данных сайта в браузере или удаления браузером.

Действие «Удалить локальные данные» удаляет ключи черновиков и истории Brand Brief Studio из текущего браузера. Экспортированные JSON/PDF-файлы, сохранённые пользователем отдельно, приложением не контролируются.

3. Серверная обработка при AI-генерации

Сам ввод текста и локальное сохранение черновика не отправляют анкету на сервер. Когда пользователь запускает AI-генерацию, валидированная анкета отправляется в endpoint генерации Brand Brief Studio.

Целевая production-архитектура обрабатывает запрос в российском контуре Yandex Cloud и передаёт вводные проекта в Yandex Cloud AI Studio для создания структурированного рабочего брифа. Собственная серверная база пользовательских брифов приложением не создаётся.

Не следует вводить персональные данные третьих лиц, специальные категории персональных данных, пароли, API-ключи и иные секреты доступа или конфиденциальные сведения клиентов. Свободные поля анкеты могут содержать персональные данные, если пользователь сам вводит сведения об идентифицируемом физическом лице.

4. AI-провайдер

Целевой провайдер — Yandex Cloud AI Studio с моделью Яндекса в российском облачном контуре. В запрос генерации входят поля анкеты, необходимые для формирования брифа, и системные инструкции, задающие структуру результата.

Приложение явно запрашивает отключение логирования prompt/output AI через заголовок провайдера. Это настройка самого запроса; production-настройки облачного аккаунта и сервиса также должны быть проверены перед запуском.

5. Технические данные

Сетевая инфраструктура неизбежно получает технические сведения запроса, включая IP-адрес, заголовки и временные метки. Приложение использует адрес клиента только для получения псевдонимного HMAC-ключа ограничения частоты запросов. Исходный адрес не передаётся в application-лог Brand Brief Studio.

Для диагностики генерации приложение может логировать случайный request ID, исход обработки, длительность, номер попытки, идентификатор AI-провайдера/модели и код ошибки/статус upstream. Текст анкеты и созданного брифа намеренно не передаётся в вызовы application logging.

6. Яндекс Метрика

Яндекс Метрика необязательна. Её тег загружается только после выбора «Разрешить аналитику». При отказе приложение выставляет официальный флаг отключения счётчика и не инициализирует Метрику.

Вебвизор отключён. Brand Brief Studio не использует session replay для намеренной записи взаимодействий с анкетой. Выбор можно изменить через «Настройки аналитики». При отзыве приложение блокирует дальнейшую работу счётчика и по возможности удаляет доступные JavaScript first-party cookies и browser-storage идентификаторы Метрики.

Отзыв действует на будущую аналитику и не может задним числом удалить события, которые уже были переданы провайдеру. В production-документации оператора должна быть зафиксирована фактическая конфигурация счётчика в кабинете Метрики.

8. Сроки и удаление

В целевой архитектуре у Brand Brief Studio нет собственной application-базы анкет или сгенерированных брифов. Локальные черновики/история остаются в браузере по правилам выше. Окно application rate limit составляет десять минут; истёкшие псевдонимные buckets удаляются при последующих запросах.

9. Выбор пользователя и права

AI-обработку можно не использовать: интерфейс сохраняет явно обозначенный локальный структурированный draft без AI. Пользователь может удалить локально сохранённые данные продукта и изменить необязательную настройку аналитики.

Запросы субъекта персональных данных и иные права будут обрабатываться оператором по контакту из раздела 1 после заполнения данных фактического оператора.
