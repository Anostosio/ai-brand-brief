Privacy in Brand Brief Studio

This page describes the actual data flows of Brand Brief Studio: what remains in your browser, what is sent for AI generation, what technical data is used, and how optional analytics works.

2. Local data in your browser

The questionnaire draft is saved in this browser so you can continue your work. Up to eight recent briefs are also stored locally for each interface language. A recent-brief entry contains the questionnaire input, generated or local output, evidence metadata, alternative directions and a local timestamp.

These records are stored with the browser Local Storage API. Brand Brief Studio does not synchronize them to an account or application database. They remain until you delete them, clear site data in your browser, or the browser removes them.

The Delete local data action removes Brand Brief Studio draft/history keys from this browser. Exported JSON/PDF files that you saved elsewhere are outside the application's control.

3. Server processing during AI generation

No questionnaire is sent to the server merely because you type or save a local draft. When you press the AI generation button, the validated questionnaire is sent to the Brand Brief Studio generation endpoint.

The target production architecture processes that request in the Russian Yandex Cloud environment and sends the project input to Yandex Cloud AI Studio to generate the structured working brief. The application does not create a server-side database of user briefs.

Do not submit personal data of third parties, special-category personal data, passwords, API keys, authentication secrets or confidential client information. A project questionnaire can contain personal data if you choose to enter information about an identifiable person.

4. AI provider

The target provider is Yandex Cloud AI Studio using a Yandex model in the Russian cloud contour. The generation request includes the questionnaire fields needed to produce the brief and system instructions defining the output structure.

The application explicitly requests disabled AI prompt/output logging through the provider request header. This is an application setting; the production cloud account and service configuration must also be verified before launch.

5. Technical data

Network infrastructure necessarily receives technical request data such as an IP address, request headers and timestamps. The application uses the client address only to derive a pseudonymous HMAC rate-limit key. The raw address is not written to Brand Brief Studio application logs.

For generation diagnostics the application may log a random request ID, outcome, duration, attempt number, provider/model identifier and upstream status/error code. Questionnaire text and generated brief content are deliberately excluded from application log calls.

6. Yandex Metrica

Yandex Metrica is optional. Its tag is loaded only after you choose Allow analytics. If you decline, the application sets the counter-disable flag and does not initialize the counter.

Session Replay / Webvisor is disabled. Brand Brief Studio does not intentionally use session replay to record questionnaire interactions. You can reopen Analytics settings and withdraw the choice. On withdrawal the application disables further counter activity and makes a best-effort deletion of first-party Metrica cookies and browser-storage identifiers accessible to JavaScript.

Withdrawal affects future analytics processing; it cannot retroactively remove events already sent to the analytics provider. The final production operator documentation must record the exact Metrica configuration used in the counter dashboard.

8. Retention and deletion

Brand Brief Studio has no application database for questionnaires or generated briefs in the target architecture. Browser drafts/history remain locally as described above. The in-memory application rate-limit window is ten minutes; expired pseudonymous buckets are removed during subsequent requests.

9. Your choices and rights

You can avoid AI processing and use the explicitly labelled local structured draft instead. You can remove locally saved product data through the interface and change the optional analytics preference.

Rights relating to personal-data processing and requests to the operator will be handled using the contact published in section 1 once the operator information is completed.
